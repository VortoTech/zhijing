# 实时 MVP 验收

## 本轮工程保障

- 原始来源不随模型遗漏而消失。`analysis.status` 区分 `complete`、`partial`、`failed`、`no_comments`；引文无效的标注不展示，也不将其解释为“没有异议”。
- 每批最多 6 条、约 14000 字符；单条不可拆分时允许超过字符软限。两个批次并发，最多重试一次；只重试未完成记录，保留已完成结果。总分析预算 90 秒，单次上游请求 25 秒。
- 模型截断、非法 JSON、遗漏记录和校验失败可触发一次重试；非 429 的 4xx 不重试。多路检索允许部分成功，但明确报告失败路数。部分结果不进入 15 分钟成功缓存，用户可重新分析。
- 流式读取上游响应，超过 2 MB 时取消；不先完整读入无限响应。取消等待不会保证撤销已经发给上游的调用，界面对此明确说明。
- 服务日志仅含请求编号、话题、模式、耗时、数量和缺口，不记录凭据、正文、评论或原始上游错误。
- `liveStatus` 默认 blocked。第一份工作为 pilot，考研为 blocked。仅凭据配置不能开放话题；pilot 还需显式 `ZHIJING_ENABLE_PILOT=1`。此开关不是鉴权机制，不应据此公开暴露服务。

## 本地联调

在本机 `.env.local` 填入 `.env.example` 中的配置，不要把密钥贴到聊天、日志或版本库。内部试用另设 `ZHIJING_ENABLE_PILOT=1`。

```sh
node --env-file=.env.local src/server.mjs
npm run smoke
npm run smoke -- --live
```

默认 smoke 只读离线样本；`--live` 会实际消耗检索与模型额度。输出仅包含数量、耗时和请求编号。退出码 0 表示本次检查完整通过，2 表示部分结果，1 表示请求/约束失败。可用 `ZHIJING_BASE_URL` 指定待验收服务。

需要至少覆盖：真实成功、无评论、空结果、凭据失效、模型截断、429/超时、部分检索失败、快速切换与重试。记录冷启动和缓存命中的耗时；额度/费用以服务商实际账单核对，当前工具不估造成本。

## 独立语义评估

1. 另外采集未用于调试的一批回答和精选评论，先冻结来源；建议首轮至少 100 条有评论回答，跨不同问题，保留真实正负例比例。
2. 人工逐条标注所有取到的评论，复核异议类别与目标句关联；争议样本二次复核。演示样本及合成单测不能替代这一步。
3. 保留完整的模型预测来源与分析状态，对齐 `id`、`sourceHash`。不要删除模型漏回或分析失败的记录来提高指标。
4. 用以下格式评分：

```json
{"name":"first-job-independent-v1","records":[{"id":"真实来源ID","sourceHash":"对应来源哈希","objections":[{"commentIndex":0,"type":"counter_example"}]}]}
```

预测文件使用阅读接口的 `records` 格式；也可以是直接分类结果包装成 `{ "records": [...] }`。

```sh
npm run evaluate -- gold.json predictions.json
```

评分报告 precision、recall、完成率及逐条 TP/FP/FN；来源哈希不同、重复记录、范围不同会拒绝评分。没有预测时 precision 为 null，而非 100%。评分匹配的是“评论下标+异议类型”，目标句关联和评论观点真假仍需人工判断。

## 开放门槛（待验收，不是已达成结果）

- 建议初始目标：独立样本异议精确率 ≥90%、召回率 ≥70%、分析完成率 ≥95%。这些是暂定产品门槛，须结合样本量、置信区间和实际用户反馈调整。
- 真实联调记录齐全，成本预算可接受；小范围用户能够找到、核对异议，而不是把标记理解为事实裁决。
- 完成公网访问/额度控制、TLS、进程托管、监控告警、版本管理与回滚流程后，才考虑开放网络访问。
- 保存模型/提示词版本、评估数据版本、日期和报告，经人工审查后再将话题 `liveStatus` 改为 approved；不能自动用单次测试通过代替审批。

目前没有真实凭据联调结果、独立人工金标准或公网部署验收。本轮提供工程机制与工具，不宣称这些条件已经满足。
