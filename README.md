# 知镜

> 别人告诉你哪边对。知镜把两边的真人原话摆出来，连评论区里当场不同意的，也一起摆出来。

- 线上地址：<https://zhijing.vortotech.com>
- 知乎黑客松 2026 · 校园新锐季 · 知识炼金场｜队伍：开心往前飞

## 它解决什么

在知乎上为「考研还是工作」「国企还是私企」「大城市还是回老家」这类选择找参考时，高赞代表共鸣，不代表适用于你。决定「适不适用」的信息散在几十条回答里，还有一部分藏在评论区——读者一句「当然我这是社招，不是应届生」，就可能让整条建议对你不成立。

知镜不替你做决定，只把社区里已有的真人讨论整理成一张对比图，每一句都能核对。

## 怎么用

1. 输入正在纠结的选择，或点首页的示例（示例秒开）。
2. 约 15–25 秒后看到：
   - **两边的理由**：左右并排，例如「选国企的人说 / 选私企的人说」。
   - **决定你选哪边**：3–5 个分叉条件，每个两条分支，例如「低回报专业 → 国企 ｜ 高回报专业 → 私企」，看你属于哪种情况。
   - **评论区的反驳**：被引用的原话下面，挂着同一条回答评论区里读者当场的反驳或补充。
3. 每句原话署名答主，「核对」当场显示它在原回答里的位置，「原文」跳回知乎。
4. 用知乎账号登录后，可以从自己的收藏里挑问题，或一键「收藏体检」：看你收藏的回答，评论区有没有人当场不同意。

查资料类问题（政策、流程、数据）会被识别并提示换问题；不是二选一的问题会提示改成「A 还是 B」。

## 为什么可信

- **原话不可能被改写**：程序先把回答切句、给每句和每条评论编号，模型只挑编号、不抄写文字，页面按编号从原文取出。
- **评论反驳逐字校验**：模型挑出的反驳必须能在原评论和原回答里逐字找到，两遍取并集、三票复核过半才保留。
- **不下结论**：只归纳结构（两边的理由、分叉条件的标题由模型归纳，页面标明），不判断哪边对。
- **如实降级**：检索失败、分析不完整、次数用完、登录失败都有真实提示，从不用示例数据冒充实时结果。

## 用到的知乎开放能力

| 能力 | 用途 |
| --- | --- |
| 知乎搜索 `zhihu_search` | 回答与文章的摘要、赞数、答主、精选评论，是全部对比内容的来源 |
| 知乎 OAuth 登录 + `/user` | 用知乎账号登录，显示昵称头像 |
| 用户数据 `/api/v1/user/collections` 等 | 读取授权用户的近期收藏，用于「从收藏里挑问题」和「收藏体检」；`/api/my/verify` 按官方要求验收五项用户接口 |

应用层做了缓存与请求去重、逐路限速（知乎搜索并发会触发限流）、每日实时次数上限。

## 技术方案

```
用户问题
  → 模型规划 6 路知乎检索词，识别查资料类问题（src/ask.mjs）
  → 知乎搜索逐路限速、去重取 60 条（src/pipeline/fetch.mjs、extract.mjs）
  → 并行：对比整理——切句编号、模型只挑编号（src/pipeline/compare.mjs）
          评论反驳识别——归类、复核投票、逐字校验（src/pipeline/classify.mjs、verify.mjs）
  → 组装页面：原话按编号取出，评论反驳挂到对应原话下（src/engine.mjs、public/）
```

- 零依赖 Node 22 服务（`src/server.mjs`）+ 原生 ES Module 前端，无构建步骤。
- 知乎登录：`src/oauth.mjs`（一次性 state 绑定浏览器、token 只在服务端内存）；登录用户数据：`src/userdata.mjs`。
- 模型：兼容 OpenAI Chat Completions 的接口（deepseek-v4-flash，关闭思考控制时延）。
- 部署：阿里云，systemd + nginx + Let's Encrypt HTTPS，见 [docs/deploy.md](docs/deploy.md)。

## 本地运行

```bash
node --version            # 需要 >= 22.9
cp .env.example .env.local   # 按注释填写；不填也能看离线示例
npm start                 # http://127.0.0.1:4318
npm test                  # 自动化测试（全部使用模拟的知乎与模型接口）
npm run check             # 语法检查
```

| 配置 | 说明 |
| --- | --- |
| `ZHIHU_ACCESS_SECRET` | 知乎开放平台 Access Secret |
| `AI_BASE_URL` / `AI_API_KEY` / `AI_MODEL` / `AI_EXTRA_BODY` | 模型接口；思考型模型需用 `AI_EXTRA_BODY` 关闭思考 |
| `ZHIJING_ENABLE_PILOT=1` | 开放实时检索 |
| `ZHIJING_LIVE_DAILY_LIMIT` | 每天最多触发多少次实时检索与模型分析，缓存命中与示例不计 |
| `ZHIHU_OAUTH_APP_ID` / `ZHIHU_OAUTH_APP_KEY` / `ZHIHU_OAUTH_REDIRECT_URI` | 知乎登录，三项缺一则登录关闭 |

## 安全

- App Key、Access Secret、模型密钥和 OAuth token 只在服务端环境变量或内存里，不进入仓库、前端响应、日志、截图或视频。
- 浏览器只持有随机会话号（HttpOnly Cookie）；日志不记录问题原文、正文、评论和用户标识。
- CSP 只允许本站脚本和知乎图片域名；分析接口在 nginx 层按 IP 限流。

## 已知边界

- 只适用于二选一的观点、经验类问题。
- 知乎接口每条内容只给正文摘要和最多 3 条精选评论，看不到完整评论区。
- 评论反驳的识别在开发样本上精确率约 63%，所以永远展示读者原话；有人反驳不代表反驳成立。
- 标题和分支说明由模型归纳，可能不全或不准；同一问题每次实时检索结果会有差异。
